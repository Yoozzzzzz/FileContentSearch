# FileContentSearch

面向 Windows 的本机文档内容检索工具：输入记得的关键词，左侧列出包含原文的文件，右侧显示命中片段及位置。

**当前状态（2026-11-19）：首版约定功能已实现，本机 Release 启动与界面复验完成；已按用户要求排除 JSON，并新增索引类型选择、结果类型筛选、完整目录树和确认后移入回收站；32 项常规 Rust 测试通过。用户已确认 100GB 是后续规模，目前没有这批资料；首版验收使用合成样本和当时 218,764 个文件的已提交索引快照，不宣称完成 100GB 验证。**

## 启动

本机已准备 C++ 构建工具、WebView2 和项目内的 Rust 工具链。正常使用可以直接运行：

```powershell
.\src-tauri\target\release\file-content-search.exe
```

首次启动先显示扫描范围，点击「建立本机索引」后扫描本机固定磁盘，并在 `D:\FileContentSearchData\` 保存索引。后续启动先打开已提交索引，再监听并复核变化；退出后不驻留。D 盘不可用或空间不足会暂停，不迁移到 C 盘。正文不会被上传或改写。点击「索引类型」可勾选扩展名并应用，也可点击「恢复默认」选择 DOCX / PDF / MD / Markdown；修改选择会在文件边界停止当前任务，清理取消类型的旧索引并按新选择继续。选择保存在专用数据目录的 `types.json` 中，重启后保留。

首次索引进行中可搜索已提交部分，按 Enter 可重新查询新提交的结果；索引任务空闲后会自动更新当前查询。界面的「覆盖尚未完整」表示扫描尚未结束或部分目录未能完整访问，可在「索引详情」查看原因。同一份生产索引只支持一个运行实例。

只测试合成数据、避免读取真实文档时：

```powershell
.\src-tauri\target\release\file-content-search.exe --demo
```

演示模式在系统临时目录创建独立的 `FileContentSearch-demo-进程号-时间` 目录，内含 10,000 份小文本、一份 30MiB 正文及 DOCX/PDF 样本，共 10,003 份文档和独立测试索引；范围只限该目录。它显式启用全部支持类型以维持固定 TXT 性能语料，不改变正常模式的四种默认类型，也不创建生产索引。该内部验收入口不提供任意路径参数，正常生产扫描排除这些演示目录。

开发或重新构建：

```powershell
. ./scripts/dev-env.ps1
npm.cmd ci
npm.cmd run tauri -- dev

# Release 本机产物
npm.cmd run tauri -- build --no-bundle

# 检查
npm.cmd run build
node scripts/tree-check.mjs
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --locked

# 可选：仅用合成文件测量首次索引吞吐，数据建在忽略的 target 临时目录
cargo test --manifest-path src-tauri/Cargo.toml --locked --release --lib measure_initial_index_throughput -- --ignored --nocapture
```

`scripts/dev-env.ps1` 仅为当前 PowerShell 会话配置忽略的 `.tools/` 中的 Rust，不修改系统 PATH。Rust 固定 1.100.0，当前 Node.js 为 24.14.1。依赖准备需要网络；实际文档处理使用本地打包资源。测试样本可用 `python scripts/generate-fixtures.py` 重建，运行应用不需要 Python。

## 文件筛选、目录树与管理

「应用并更新索引」提交后立即关闭弹窗，在主页面显示后台状态；等待当前文件结束、保存选择和清理旧索引时仍可操作搜索。重建使用页面确认框，确认后立即关闭并显示排队/准备状态；不会使用阻塞脚本的系统确认框。状态读取和提交命令通过后台线程执行，等待期间禁止重复提交，失败在主页面显示原因。

- 「索引类型」决定哪些文件会进入索引；首次默认仅选择 `docx pdf md markdown`，JSON 不提供选项。已保存的自选类型优先，升级不会覆盖；「恢复默认」可重新选四种默认类型。至少选择一种类型，取消类型只清理索引记录，原文件保留。
- 左侧「文件类型」仅筛选本次搜索，后端在正文读取和结果分页前按扩展名过滤，不改变索引设置。
- 匹配文件按完整磁盘/目录层级展示，可单独展开/折叠或全部展开/折叠。目录数字是当前已加载的匹配文件数；搜索未完成时带“+”，可继续加载。↑/↓ 选择，←/→ 折叠/展开或进入父子节点，Enter 打开选中的文件。虚拟化同时覆盖目录行和文件行。
- 选中文件后点击「移入回收站」，确认框显示完整路径，取消不会操作文件。确认后仅处理该文件，并同步提交索引删除；可在 Windows 回收站恢复，应用运行时会重新检测恢复的文件。
- 删除命令只接受当前查询编号和文件编号，拒绝任意路径、过期查询、越界文件、链接/占位符、目录，以及大小或修改时间已变化的文件。通过 Windows `IFileOperation` 要求回收，回调拒绝非回收删除；没有永久删除选项，不主动提权。若源文件已回收但索引提交失败，会显示错误并暂时关闭旧索引搜索，等待复核恢复。
- Windows 回收站可能由用户或系统设置清理，不是长期备份。测试只回收临时合成样本，不操作私人文档。

## 已实现与已验证

- TXT/Markdown/代码文本、DOCX 正文与表格、文字版 PDF 提取；可见的损坏、加密、解码、超限、无文本等错误。
- Tantivy 持久化一元/二元字符候选索引，ASCII 大小写归一化后校验完整字面子串。特殊字符不解释为查询语法。
- 快照分页，每批最多 50 个文件；过滤预算耗尽时继续分页，完成前显示「已找到数量+」，不把候选数冒充命中总数。
- TanStack Virtual 目录树、可见行摘要、按需高亮预览、行号/段落/页码；键盘选择、快速连续查询保护、打开文件/目录、复制路径。脚本文本通过记事本打开，避免按扩展名执行脚本。
- 全机固定磁盘扫描及排除规则，单写入协调者、先监听后复核、变更合并、监听错误后的复核、手动刷新和取消；重建保留旧索引，完整成功后切换。
- 数据目录归属标记、原子发布配置、剩余空间检查、过期快照释放、索引代清理，以及失败目录下旧记录的保护。
- WebView2 配置保存在 `%LOCALAPPDATA%\FileContentSearch\WebView2`；排除自身配置、演示数据及构建工具目录。程序安装位置从 Windows 注册信息读取，用户文档中名为 `Windows` 的普通目录仍可检索。

取消重建或目录复核失败时不发布不完整的新索引。提取失败的文件从有效搜索中排除，并在「索引详情」中保留最近 50 条原因；失败总数单独累计。索引内容包含原文副本，默认没有加密。查询闲置三分钟后释放快照，继续操作时需重新搜索。

## PDF 解析边界与决定

用户已确认采用同一 EXE 的临时解析子进程，已接入正式扫描调用。最多一个 PDF 解析任务：父进程先设置 Windows Job Object，再通过标准输入提供数据；限制进程提交内存为 512MiB、运行时间 60 秒，取消/父进程退出时结束子进程，不安装服务或后台驻留。此结构是经用户确认对初始单进程方向的调整。

源文件上限 32MiB、输出文本 64MiB、DOCX 实际 XML 解压累计 128MiB、ZIP 条目 4096、XML 深度 128、位置记录 100 万；PDF 页数 1 万、非图像流累计解码 128MiB。超限报错，不把截断文本作为完整索引。PDF 库内部在检查解压长度前发生的分配仍由操作系统进程内存预算约束；解析警告或错误使该文件失败，不接受部分页面成功。

资源探针（20 次、Release、包含进程启动到退出）测得中文两页样本 P50 16.35ms / P95 17.69ms，最大观测提交内存 6.32MiB；64MiB 预算能拒绝 128MiB 分配，关闭任务对象能终止超时子进程。这不是复杂 PDF 的峰值或最终全应用内存。参考 [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

现有 PDF 样本覆盖显式 ToUnicode、两页及简单双栏，不能保证所有字体和阅读顺序正确。30MiB DOCX/PDF 测试的额外体积来自未使用条目/流，不代表同体积复杂正文。OCR、页眉页脚、批注与嵌入对象不在首版范围。

规划时只读检查的机器基线：i5-13600K、约 32GB 内存；D 盘约有 267GiB 可用空间。磁盘余量是当时的快照，正式索引和重建前必须重新检查。原始文档大小不等于提取文本或索引大小，不根据 100GB 原文件直接推算索引占用。

## 技术选择

项目采用 **Tauri 2 + Rust + Tantivy + TanStack Virtual**。界面使用原生 TypeScript / HTML / CSS，由 Vite 构建；不引入 React。文件处理和检索在 Rust 中执行。

| 部分 | 选择 | 用途 |
| --- | --- | --- |
| 桌面外壳 | Tauri 2 | 窗口、系统交互和前后端 IPC；Windows 使用 WebView2 |
| 界面 | 原生 TypeScript / HTML / CSS / Vite | 搜索框、左右分栏、结果状态和文本片段 |
| 大列表 | TanStack Virtual（`@tanstack/virtual-core`） | 直接使用核心虚拟化能力，仅渲染可见行及少量缓冲行，配合后端分页 |
| 本地检索 | Rust / Tantivy | 中文字符索引、候选筛选、精确匹配及持久化 |
| DOCX 提取 | Rust `zip` + `quick-xml` | 按需读取文档 XML，提取正文和表格文本 |
| PDF 提取 | Rust `pdf-extract`（首选验证对象） | 按页提取文字，先验证中文和复杂排版样本 |
| 数据保存 | Tantivy 存储字段；小型 JSON 配置 | 保存文本、位置、文件元数据和配置，首版不额外引入数据库 |
| 文件变更 | Rust `notify` + 目录复核 | 接收变更通知并合并重复事件，启动及监听异常时检查遗漏 |
| 验证 | Rust 内置测试；前端交互测试 | 核心逻辑使用 `cargo test`；前端测试工具建工程时确定 |

Tauri 使用系统 WebView，Rust 核心进程负责业务逻辑，前端通过 IPC 请求结果。它适合减少随应用分发的浏览器组件，但实际内存必须包含关联的 WebView2 进程。[Tauri 进程模型](https://v2.tauri.app/concept/process-model/)

TanStack Virtual 提供列表虚拟化能力，不负责数据检索和分页；它减少 DOM 数量，不能自动消除数据传输、文本高亮或组件重复更新的开销。[TanStack Virtual](https://tanstack.com/virtual/latest/docs/introduction)

选择 Rust 原生解析路径以控制依赖、进程启动和中间数据转换成本；实际提取速度取决于库实现及文档特征，不能仅凭语言认定开销已经最低。首版不依赖 Office 自动化、Python、Java 或外部转换服务。

## 性能目标与测量口径

以下是规划时确定的优化目标；已测结果见上方验证表，尚未完成的规模测试不作性能承诺。

| 目标 | 验证口径 |
| --- | --- |
| 普通查询首屏 100ms 内 | 实施验收使用固定普通查询集的端到端 P95 ≤ 100ms；索引就绪、热缓存条件下测量，冷缓存及极高频词单列 |
| 应用安装包控制在几十 MB 以内 | 测 Release 安装包，明确是否含 WebView2 运行时，单独报告安装后体积与索引大小 |
| 空闲内存控制在几十 MB | 索引完成并稳定空闲后，统计应用及关联 WebView2 进程的私有工作集；另报索引/查询峰值 |
| 检索内核争取亚毫秒级 | 次级挑战目标；分别报告引擎查询、精确校验及端到端延迟，不能用引擎耗时代替用户等待时间 |
| 万级结果滚动保持流畅 | 用至少一万条可访问结果测试滚动、选中和预览；记录帧耗时与长任务，目标帧预算按显示刷新率确定 |
| 全程本机处理，无运行时网络依赖 | 断网验证启动、索引、查询、预览和文件打开；前端资源随应用打包，无远程字体、CDN、遥测或自动更新请求 |

基准必须记录 CPU、内存、硬盘、软件版本、文件数、原文件与提取文本总量、查询长度和命中率；同时覆盖一字、两字、长词、高频词及无命中查询。记录冷/热缓存下的 P50/P95 延迟、首轮与增量索引吞吐量、索引体积和提取准确性。亚毫秒级作为挑战目标，不承诺所有规模和所有查询都达到。

首屏计时从有效输入完成开始（中文输入法以组合输入提交为准），到当前查询结果和可见行摘要完成绘制结束，包含防抖、调度、IPC、查询及渲染；空白骨架不算完成。结果分页默认先取 50 条元数据，仅生成可见行摘要，右侧详细预览另行按需测量。普通查询集在优化前固定，包含常用中文双字和长词，不在测试后把慢查询随意移出集合。精确总数和剩余结果不阻塞首屏。

Windows 运行需要 WebView2。首版仅供本人使用，检查并复用本机兼容运行时；如缺失，可在开发或安装准备阶段联网安装，不制作内置完整运行时的离线安装包。应用的解析、索引和检索仍全部本机执行，前端资源随程序打包。[Windows 安装选项](https://v2.tauri.app/distribute/windows-installer/#webview2-installation-options)

包体和空闲内存的几十 MB 目标属于优化方向，优先级低于查询及索引速度。不得为了表面满足内存数字而排除 WebView2 进程，或把大量成本转移到每次查询。开发依赖下载及系统管理的运行时更新不算文档检索的网络依赖。

- 发现本机固定磁盘，按默认排除规则递归建立内容索引；展示实际扫描范围、排除项和无法访问的目录。
- 启动时复核文件变化，软件运行期间自动增量更新；保留手动刷新与重建入口。
- 检索 TXT、Markdown、代码文本、DOCX 和文字版 PDF。
- 输入关键词后，左侧按文件展示名称、完整路径、类型和一条命中摘要；同一文件不重复列出。
- 右侧显示多个命中片段并高亮关键词；纯文本提供行号，PDF 提供页码，DOCX 提供段落位置。
- 支持打开原文件、打开所在文件夹和复制路径。
- 显示索引进度、最后成功更新时间、失败或跳过原因；任务可取消，界面保持响应。

- 所有文档处理与检索在本机完成，不需要账号、云端服务或模型 API。

右侧预览是提取后的文本，不承诺还原 Word/PDF 排版。DOCX 段落位置不是 Word 页码；没有可靠定位信息时，应明确显示不可用。

## 检索与预览规则

输入按普通文字处理，采用连续子串匹配，不解释为正则表达式或布尔查询。中文不要求空格分词；英文 ASCII 大小写不敏感。保留原始提取文本用于预览，检索文本与输入使用相同的 ASCII 大小写归一化规则，不自动做繁简或同义词转换。

首版采用一元/二元字符索引：一字查询查一元项，两字及更长查询提取连续二元项，在倒排索引中筛选候选，再核对候选文本是否包含完整关键词。避免把短词全库扫描作为正常查询路径。字符索引会增加索引体积，常见单字仍可能产生大量候选，需纳入性能测试。

先把此方案作为可验证的基线。如果大量候选正文解压与校验影响首屏目标，在检索阶段内升级为保留字符位置的 tokenizer 与连续短语查询，重新验证顺序、重复字符及边界，并比较索引体积。Tantivy 的 PhraseQuery 要求索引记录词项位置；不能直接把内置 NgramTokenizer 的相同位置值当作连续位置使用。[PhraseQuery](https://docs.rs/tantivy/latest/tantivy/query/struct.PhraseQuery.html)

| 输入 | 处理方式 |
| --- | --- |
| 空输入 | 不执行全库查询，提示输入关键词；仅含空格的非空输入仍按字面匹配 |
| 一个 Unicode 字符，如「合」 | 查询一元字符索引，分批返回有效结果 |
| 两个 Unicode 字符，如「合同」 | 查询对应二元字符项，核对文本并生成片段 |
| 更长关键词，如「合同签署」 | 求「合同」「同签」「签署」等二元项的候选交集，再核对完整连续子串 |
| 包含引号、`AND`、`%`、`_` 等 | 仍按字面文本查询，不改变检索含义 |

Tantivy 的 NgramTokenizer 可配置字符片段长度，但其当前内置实现将同一字段值的 token position 设为 0。不能直接把这些词项组合当成具备顺序保证的短语匹配；首版使用显式词项查询和候选文本精确校验，不把用户输入直接交给查询语法解析器。[NgramTokenizer 文档](https://docs.rs/tantivy/latest/tantivy/tokenizer/struct.NgramTokenizer.html)

索引与精确校验基于完整提取文本，不因预览分块漏掉边界关键词。保留行、段落或页码的对应关系；Rust 返回文本片段及高亮段，不让前端混用 UTF-8 字节偏移与 JavaScript UTF-16 索引。

每次查询固定索引快照与稳定排序，后端分批筛选到足够的有效命中再返回；不因只验证前一批候选而漏报后续结果。未完成精确校验时不宣称最终总数；预算耗尽要明确显示未完成并支持继续。后端分页与前端虚拟化配合，不能把所有正文或万条完整片段一次性经 IPC 发送到界面。

前端只渲染可见行与有限缓冲行，列表摘要和右侧预览按需获取，使用稳定文件标识维护选中状态。查询编号同时约束结果、总数与预览，防止旧请求覆盖新查询；预览切换也要校验文件标识。

## 文本提取与索引更新

流程为：**发现固定磁盘并排除无关目录 → Rust 枚举与解析 → Tantivy 建立索引 → 查询并精确校验 → IPC 分批返回 → 虚拟列表与片段预览**。首次解析和增量更新在后台完成，日常查询不重新解析所有原文件。

扫描只使用当前用户已有权限，不要求管理员运行。排除目录在递归进入前判断，Windows 与程序安装目录从系统位置获取；不把整个用户目录或 AppData 一并排除。网络盘、移动介质、目录链接/联接点及未下载的云文件占位符不纳入默认扫描；应用数据目录始终排除，避免索引自己的缓存。对权限不足和未支持格式给出可见统计。

| 格式 | 提取边界 |
| --- | --- |
| TXT / MD / 代码 | 按明确的扩展名白名单读取；支持 UTF-8、带 BOM 的 UTF-16；无法解码的文件报告原因，不悄悄替换乱码 |
| DOCX | 首版覆盖正文段落及表格文本；保留文本 run 之间的连续性，以及段落、单元格之间的边界；页眉页脚、批注和嵌入对象暂不纳入 |
| 文字版 PDF | 按页提取文本并保留页码；复杂排版和字体映射可能影响阅读顺序或字符准确性；空提取应提示可能需要 OCR |

文本扩展名白名单为：`txt md markdown rs ts tsx js jsx toml yaml yml html css xml csv log py java c h cpp hpp cs go sql ps1 sh`。扩展名不区分 ASCII 大小写；编码规则对这些文本文件一致。按用户要求，JSON 不纳入检索；启动时在开放搜索前清除旧索引中已不支持的文件类型记录，包括 `.json` / `.JSON`，无需手动重建，原文件保持不变。

DOCX 使用 `zip` 读取需要的条目，使用 `quick-xml` 的流式接口解析文档 XML，不把整个压缩包解压到磁盘。按命名空间与文档关系识别主文档，处理文字、空格、制表符、换行及表格边界；限制条目数、实际解压字节数和 XML 深度。[zip](https://docs.rs/zip/latest/zip/)、[quick-xml](https://docs.rs/quick-xml/latest/quick_xml/)

PDF 使用 `pdf-extract` 在临时子进程中按页提取；按页输出不意味着解析器只占用单页内存。已验证的中文字体映射、多栏、空页及错误样本与资源限制见开头记录，复杂文档兼容性仍以实际提取结果为准。[pdf-extract](https://docs.rs/pdf-extract/latest/pdf_extract/)

索引设计约定：

- 每个有效文件对应一条逻辑记录，保存规范化路径标识、展示路径、大小、修改时间、完整提取文本、位置与格式；Tantivy 提交承载版本与更新时间，失败文件从有效记录中排除，任务错误单独显示。配置使用小型 JSON 文件。
- 启动复核和手动刷新通过路径、大小、修改时间筛选变化；监听到内容变化时，即使这些元数据未变也重新提取。保留重建入口，处理软件退出期间元数据不变但内容变化等情况。
- 使用单一写入协调者，替换文件时按稳定标识删除旧记录并加入新记录，在同一提交中发布；写入失败时保留上一已提交版本并显示未刷新状态。提取失败的文件标记过期或从有效结果中排除。
- 查询使用已提交快照；提交后显式重载读取器，再报告新结果可见。不要假定默认自动重载与提交返回同步。[IndexReader](https://docs.rs/tantivy/latest/tantivy/struct.IndexReader.html)
- 只有相关目录完整扫描成功后，才清理确认已经删除的文件记录；取消、目录离线或权限错误不能当成文件删除。
- 对源文件和解压/提取量分别设限，正常路径至少覆盖用户的约 30MB 单文件；源文件大小不代表其解压或解析内存大小。超限报告原因，不静默截断。
- 软件运行期间监听创建、修改、删除和重命名，按路径合并短时间重复事件；文件仍在写入时延迟重试，读取前后校验版本。先建立监听再启动目录复核，将扫描期间的变更重新核对，避免竞态漏更新。
- 监听队列溢出、监听错误或事件不确定时标记对应范围需要复核；不能将事件当作唯一事实来源。不同编辑器保存方式可能不同，大目录监听可能漏事件，必须测试这些情况。[notify 文档](https://docs.rs/notify/latest/notify/)

文件解析与索引使用有界后台任务和有限队列，限制并发数及索引写入内存；不为每个文件无界创建任务，不在 UI 或异步执行器线程中长时间执行阻塞解析。每累计 256 个文件、2MiB 提取文本或距离上次提交超过 2 秒，在当前文件边界提交；一轮扫描结束或取消时也提交已完成部分。Tantivy 写入缓冲为 32MiB，单个大文档的瞬时占用受独立提取边界约束。取消时停止调度新任务并在文件/批次边界检查状态；取消超时等待不等于正在运行的同步解析已经终止。

索引与重建暂存数据放在 `D:\FileContentSearchData\`，WebView2 配置保存在 `%LOCALAPPDATA%\FileContentSearch\`。D 盘不可用或空间不足时暂停写入并说明原因，不自动迁回 C 盘。重建先保留旧索引，完整构建并提交新索引后再切换；创建目录时不覆盖同名的非应用数据。

索引含有文档文本副本，并非加密保险箱；不要放入仓库、公共目录或同步目录。索引和预览只读原文件；只有用户选中文件并确认「移入回收站」后才移动该文件。索引清理或重建只处理自己拥有的数据，不能因磁盘空间不足删除源文档。

## 项目组织与开发顺序

当前工程包含以下基础结构；索引、扫描、资源隔离与搜索模块已接入：

```text
src/                         # 原生 TypeScript / CSS 检索界面
src-tauri/
  src/                       # lib、engine、filesystem、index、worker、extract
  tests/                     # 集成测试与 fixtures 合成样本
  capabilities/              # 最小权限配置
  Cargo.toml
  Cargo.lock
  tauri.conf.json
scripts/                     # 工具链环境、合成样本、界面性能和内存测量
package.json
package-lock.json
```

保持一个 Tauri 应用和清晰的 Rust 模块；前端只负责交互，后端负责文件访问、解析、索引和检索。不预建插件系统、通用 Repository、多进程解析框架、额外数据库或独立 HTTP 服务。

以下是原定五阶段路线。阶段 1–4 及本机 Release 交付已完成；阶段 5 已完成合成数据和现有索引快照的测量。用户明确确认 100GB 资料尚未准备，完整 100GB 容量验证留待资料就绪后进行，不把它写成已经通过。

| 阶段 | 实现内容 | 可检查的完成条件 |
| --- | --- | --- |
| 1. 基础工程与提取验证 | 最小 Tauri + 原生 TS 工程、Rust 模块和测试；TXT/DOCX/PDF 提取、位置映射及失败状态 | 本机能启动空壳并调用 Rust；自建中文三格式样本提取正确；DOCX run/表格、PDF 页码及错误文档有测试；约 30MB 样本可处理 |
| 2. 索引与检索基准 | 字符索引、字面查询、精确匹配、分页、片段、持久化与提交重载；用小型代表集测量后逐步扩容 | 与参考连续字符串匹配逐项比对，无误报漏报；重启结果一致；记录延迟、索引体积、提取/建索引吞吐量和峰值内存，瓶颈明确 |
| 3. 可用桌面界面 | 搜索输入、虚拟结果列表、摘要与右侧预览、文件打开、进度和错误状态 | 真正三格式查询跑通；一万条结果可滚动及键盘选中；中文输入法正常；旧结果/旧预览不覆盖新状态；测得端到端延迟 |
| 4. 全盘扫描与增量更新 | 固定磁盘发现、默认排除、启动复核、运行期监听、事件合并、重试、取消和重建 | 新增/修改/删除/重命名和编辑器替换保存均正确；权限失败、磁盘不可用、事件溢出和中断不误删索引；已完成部分可搜索 |
| 5. 100GB 验证与本机交付 | 在自建测试通过后，对用户目标文档运行应用索引；性能优化、Release 构建与使用说明 | 记录所有支持/失败/跳过数量；普通查询集端到端 P95 ≤ 100ms 为验收目标，未达标明确报告；冷缓存、高频词、内存、索引大小和包体均有记录；本人电脑可启动使用 |

阶段 2 先用自建样本验证正确性，再用代表集估算资源需求。现有固定磁盘索引通过正常应用入口启动，测试脚本不自行启动全盘扫描；真实文档不进入代码仓库或日志，验收仅记录汇总指标。交付时正常程序已恢复运行，继续启动复核与增量更新；没有把合成吞吐直接换算成 100GB 索引分钟数。

## 实际模块与接口

保持模块边界即可，不为每个模块创建抽象层或独立进程。

| 模块 | 责任 |
| --- | --- |
| `filesystem` | 固定磁盘、排除规则、目录归属、空间检查与索引代切换 |
| `extract` | 格式识别、文本与位置提取、编码/损坏/加密/超限分类 |
| `index` | 字符索引、文件替换、提交重载、快照分页、精确校验与片段缓存 |
| `engine` | 单写入协调、目录扫描、通知合并、有限重试、取消重建与会话释放 |
| `worker` | 同一 EXE 的临时 PDF 解析子进程、资源预算、协议与取消 |
| `lib` 与前端 `main.ts` | 参数验证与 IPC；搜索状态、虚拟列表、预览和系统打开操作 |

当前只允许一个索引任务，无额外任务标识或通用任务系统。前端每秒查询状态；搜索及预览按需调用，不持续推送正文。

| 操作 | 约定 |
| --- | --- |
| `refresh_index(rebuild)` | 排队刷新或重建；运行中拒绝第二个索引任务，不显示虚假的精确百分比 |
| `cancel_index()` | 停止新调度，在文件/提交边界结束；PDF 子进程可中止，状态在实际退出当前任务后变为暂停 |
| `set_index_types(extensions)` / `recycle_selected(request, id)` | 有界队列交给单一写入协调者；类型选择持久化后复核，回收后提交索引，失败返回可展示原因 |
| `search(request, query, extensions?)` / `next_page(request, offset)` | 请求编号绑定快照，offset 必须等于已返回数量；返回文件元数据、已找到数量、是否完成及测量耗时 |
| `previews(request, ids, detail)` | 每次最多 24 个摘要或 1 份详细预览，返回同一快照的行/段/页与高亮文本段 |
| `open_selected(request, id, folder)` / `selected_path(request, id)` | Rust 校验结果归属及目录范围；系统打开或返回选中文件路径，前端仅在用户点击后复制 |
| `engine_status()` | 返回阶段、范围、已索引/已检查/累计失败或跳过数量、最近 50 条原因、提交时间与版本；区分范围不完整和真实无命中 |
| `index_statistics()` | 打开索引详情时按当前已提交快照汇总文本/DOCX/PDF 数量与源文件总大小，使用索引元数据，不触发正文提取 |

首批默认 50 条元数据，后续按滚动需求加载；可见摘要批量请求。索引任务使用有界队列，从少量解析工作线程开始测量，查询任务优先；调优参数先作为内部常量，不为尚无需求的参数制作设置界面。未完成全部计数时显示已找到的结果数量及继续加载状态。

## 验证重点与交付边界

- **正确性**：一字/两字/长词、重复字符、空格、引号、标点和非 BMP 字符；所有词项存在但完整连续关键词不存在的反例；分页不重不漏。
- **提取质量**：中文 DOCX 正文及表格、跨 run 文本、PDF 中文字体映射与页码；错误、加密、扫描件或不支持格式有明确状态。
- **一致性**：新增、修改、删除、重命名、边写边读、编辑器替换保存、提交失败、监听溢出、暂停/退出/重启和新旧索引切换；失败与离线不能触发误删除。
- **交互**：输入法、快速连续查询、滚动时加载、键盘导航、快速切换预览；更新索引期间界面可操作。
- **性能**：使用本机 Release 程序，记录端到端 P50/P95、冷热查询、100GB 索引吞吐、整组进程空闲/峰值内存和磁盘占用；正确性先于速度。
- **交付**：本人电脑可运行的 Release 程序、已验证的启动/构建/测试步骤、索引位置与重建说明、支持格式和已知限制。不制作企业部署、自动更新或完整离线运行时分发方案。

开发环境采用 Windows、Rust stable MSVC 工具链、Microsoft C++ Build Tools、Node.js 和 WebView2。工具链、依赖版本与 Cargo/前端锁文件已固定，具体版本见开头。[Tauri 环境要求](https://v2.tauri.app/start/prerequisites/)

基础工程的实际命令、依赖版本与验证结果见本文开头。当前 Release 已具备检索界面与自动索引，完整验收状态以本文开头的实测记录为准。

## 首版验收

- 文件名不含关键词而正文含关键词时，能够找到文件。
- 「合」「合同」「合同签署」都能命中正确文件；中文、英文大小写及特殊字符遵守同一查询规则。
- 包含所有二元项但没有完整连续关键词的文档不能误报；候选分页不能漏掉后续有效命中。
- TXT、DOCX、文字版 PDF 各有可重复的样本；预览高亮与实际命中一致，位置标记正确。
- 修改、删除文件后自动更新，结果与磁盘内容一致；程序退出期间发生的变更在下次启动时复核；重启可立即使用已提交的索引。
- 损坏、加密、无权限、无可提取文本或超限文件不会中止整个批次，且有可见原因。
- 快速连续查询、取消索引、扫描中断和目录不可访问时，不显示旧查询覆盖的新结果，不误删有效索引。
- 所有检索均在本地完成，原文档内容、时间戳和权限不被主动修改。
- 全机扫描遵循排除规则，D 盘保存索引；万级结果下滚动、键盘选中及预览切换可用，普通查询首屏按 100ms 目标验证。运行时已具备后，断网不影响本地检索。
